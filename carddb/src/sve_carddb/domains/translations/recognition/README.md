# Finite source recognition

These modules classify lexical slots for the four-layer source core. They receive
its exact source partition and Unicode trace; they do not split or normalize
fields through another recipe. `analysis` finds positions and unresolved causes,
`candidate_matching` applies enabled finite rules, and `rules` reads the current
authored matcher selection.

Signed, identifier, ordinal and reminder exclusions run before ordinary numeric
ownership. A matcher cannot claim an already-owned position. Numeric values use
JavaScript’s safe unsigned range; signs remain literal source text. Header roles
come from named grammar groups. Positive and negative synthetic cases preserve
the frozen N0 recognition behavior.

`references` and `adopted_references` resolve exact current glossary and vocabulary
references. Card names require one complete concept; substring mentions cannot
become semantic bindings. Missing or ambiguous references keep their diagnostic
causes. Recognition alone neither adopts a frame nor authorizes a translation.
The four-layer classifier assigns the registered type, role, domain and unit;
the source core and SourceBinding boundary retain exact owner positions.

Rules belong to the installed program and enabled switches come from the working
tree. Empty selection enables no rules. There is no historical source inventory,
producer pin, approval receipt or second resolution parser.
