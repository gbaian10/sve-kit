# Finite source recognition

These modules classify lexical slots for the four-layer source core. They receive
its exact source partition and Unicode trace; they do not split or normalize
fields through another recipe. `analysis` finds positions and unresolved causes,
`candidate_matching` applies enabled finite rules, and `rules` reads the current
authored matcher selection.

Signed, identifier, ordinal and reminder exclusions run before ordinary numeric
ownership. A matcher cannot claim an already-owned position. Numeric values use
JavaScript’s safe unsigned range; signs remain literal source text. Header roles
come from named grammar groups. Positive and negative synthetic cases preserve
the frozen N0 recognition behavior.

`references` and `adopted_references` resolve exact current glossary and vocabulary
references. Card names require one complete concept; substring mentions cannot
become semantic bindings. Missing or ambiguous references keep their diagnostic
causes. Recognition alone neither adopts a frame nor authorizes a translation.
The four-layer classifier assigns the registered type, role, domain and unit;
the source core and SourceBinding boundary retain exact owner positions.

Rules belong to the installed program and enabled switches come from the working
tree. Empty selection enables no rules. There is no historical source inventory,
producer pin, approval receipt or second resolution parser.

## Frozen N0 guard limitations

1. `END` includes `」`, while SELECT and explicit-rule lookaheads do not. Six
   private unmatched rows expose this existing gap; it is not a regression.
2. Bodies use NFKC and N/X replacements, while reminders keep original spelling.
   Shared regex character classes and colon handling therefore differ by input.
3. Counter names occur in both `explicit_rules` and `four_layer_numbers`, and
   alternation joins do not call `re.escape`. Any future change must update both.
4. N/X placeholders share glyphs with English letters. The current corpus has no
   collision; transformation tags preserve which positions are placeholders.
5. A guard change can silently turn a translation into whole-field fallback.
   Every guard change must attach a complete corpus comparison by field.

These limitations are documented without expanding the frozen numeric or sentence
recognition rules. N1 source semantics belongs to #380/#499.

## N1 source derivation

`four_layer_derivation.derive_source` is the production source entry point. It
uses the current source partitions, Unicode units and adopted classifier catalog.
Its frames use `four-layer-jp-v4`, the single version accepted by the production
authored and DB readers. The normal build derives N1 source fields before matching
frames. Frozen N0 lexical and numeric rules remain the registered foundation,
without a second production reader.

Complete `【keyword】` lines obtain required Concept leaves, including every
repeated source occurrence. The standalone `{クイック}` construction requires the
exact `term:ability.quick` concept in category `ability` and a normal spell's
effect-field context to resolve as a shared card-field projection. Conditional,
granted, compound or section uses do not acquire this projection. Catalog entries
alone do not register new Quick aliases. Missing or ambiguous concepts prevent a
binding; unknown whole-line semantics retain occurrence-scoped pending frames.

The source entry derives closed body operands for owners, zones, deck positions,
phase triggers and card filters, the three registered omitted-owner rules, NC/SC
aliases and four threshold ability names. Reminder/header boundaries and opaque
modifiers remain intact; local leaves never resolve unknown whole-line semantics.
Source verification checks the complete current construction and requires CardNP
to cover every filter of its operand. Fixed structural rules belong to v2; existing
lexical/numeric rules still use enabled switches and propagate their actual
low_confidence. Disabled dependencies can leave an unmatched source or fallback.

Renderer v3 uses finite forms with exact roles and checks necessary references by
slot and concept member. A classifier argument used only to choose grammar is not
a displayed concept. Unused pure omitted owners do not require a label; displaying
them uses their own slot and ordinary quality/range dependencies. Its presentation
version is independent of the production normalizer; rendering a frame grants no
DSL qualification.
