# 常見效果的共用本體

AI 可直接依卡文撰寫 DSL。`admission: light` 用於同語義本體的 1～2 張不同遊戲卡；同語義用途達 3 張時整理為 `admission: shared` 共用本體，集中做一次語義審查與相關對局行為測試。重印／異圖按永久 CardId 去重；`author check` 的 `body_usage` 提供整理建議，第三張不追溯阻擋已合併卡片。

## 共用邊界

等價句子可共用具名本體，不必先有相同 FrameId 或完成來源分類器。能力頭、付款位置、控制圖、目標／結算選取時點與期限仍須符合卡文；新增用途主要核對參數、能力頭與上下文。不同條件或時點不能因都含抽牌而視為相同模板。

本體保留參數型別；用途提供實值。展開後通過相同 DSL Schema、scope／binding 良構與 runtime 能力檢查。跨行能力以 `covers` 列出覆蓋行；提醒／排版用 `ignored` 明示，不能默默漏掉能力。

## 測試與審查

常見本體審一輪；長尾使用已支援機制時，相關行為測試過即可合併，隨後抽查。不規定每卡案例數或固定五類邊界。新增付款、事件、取代或私有資訊機制時，審查放在該次引擎改動。

改本體時跑受影響測試，完整回歸交 CI。無需三卡兩模型資格、來源反譯證明、逐用途 canonical bytes 比對、normalizer 全庫重鍵、機器錨點或驗證 JSON。真正 disputed／未決裁定只阻擋受影響卡；來源分類 pending 本身不是裁定爭議。

## 整卡替換

所有面、本文與 sections 的非空行必須有能力或明示非能力覆蓋，同卡可混用輕量與共用本體。卡片／面永久身分及索引閉包保留，原型與 current 在同次寫入切換，不能重複執行或失敗後回退原型。token 定義不得當成母卡能力；尚未支援的 token 身分接線及 runtime 機制仍明確拒絕。
