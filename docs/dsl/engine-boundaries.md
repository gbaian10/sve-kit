# 引擎執行與資訊邊界

本文件定義 DSL 引擎的規格要求，不表示原型已完成驗收。型別與程序依 [IR 詞彙](ir-vocabulary-1.0.md)。

## 權威狀態與觀察

每局只有一份權威狀態及一套提交管線。決定描述保存 actor、合法 domain、可見性、execution 與 occurrence；續體只在 authority 保存待續步驟。
玩家與 AI 僅取得 Observation 及獲授權的 DecisionView，不取得完整 state。內部事件與歷史事實經投影後才對外提供，可省略或匿名化私有部分。
未公開隱藏物件不能帶可跨區追蹤的固定 ID；公開歷史可以保存曾見資訊，但不得連到目前隱藏 slot。
卡片印刷資料引用有版號快照，不能在引擎維護第二份卡表。

新增動作須明定 receipt、可見性與續體邊界；未知 read、event、欄位及缺少 capability 均於載入時附來源位置拒絕，不執行任意 callback。
權威重播保存決定、隨機輸入及其版本，觀看者仍適用相同投影；本機重播不構成公開 CDN 永久保存快照的承諾。

## 付款交易

合法性預演與正式提交共用規則管線。取消付款須回復 state、RNG、歷史事實、待機、模式使用及一次性額度；不能以另一套簡化 can_pay 代替。
需要玩家輸入的隨機付款不得先公開未提交的隨機結果再讓玩家取消。預演所需隨機資訊只在 authority 處理，並隨同一提交記錄保存。
receipt 只保存所需快照與引用；完整回復資料另由交易機制持有，不必每份 receipt 複製完整 state。

## 跨玩家與讀值

各玩家程序依 [IR 的 K.each-player](ir-vocabulary-1.0.md#4-receipt控制組合與付款) 按階段橫跨玩家，不能每位玩家先跑完整本文。
階段內若含容量、守護等選擇也要計入，不能只憑外層節點判為 nonchoice；無法證明者拒絕含糊 lowering。
二席 runtime 保留 PlayerRef／PlayerSet 的量詞差別，多人規則未定義時明確拒絕，不以陣列第一項代替選擇。

`define` 是純表達式別名，依每次使用點的 read 時點展開；同一指示內重複讀取使用相同開始視圖，跨指示可讀改變後的場面。
普通 apply 捕捉指示開始的集合，明示 AtPlay 的效果依該時點；static selector 動態求值。
同一權威特徵視圖供合法性、read、事件與觀察共用，cache 不能有規則副作用。

## 條件效果的選擇省略

依 [R-0004](../../authored/rules/rulings/R-0004.yaml)，DSL 保留「先選對象，再於結算時檢查條件」；
條件不成立只略過其管轄的效果，不能把目標選取改成條件成立後才開始。
例如艾茲迪亞的變成護符與後續賦予能力都放在同一條件範圍，段落範圍依 R-0002／R-0007。
目標確定可能產生 [E.targeted](ir-vocabulary-1.0.md#7-事件cause-與誘發) 所述的事件；一般 select 或費用材料選取不因此變成目標事件。

引擎可自動略過無意義的選擇，UI 不顯示選擇畫面：選擇當下已能確定條件不成立，
且所有合法候選對象都沒有會對這次「被選擇」反應的能力，選誰的結果都相同。
只要有候選對象會反應，就依規則保留玩家選擇；不能以效果本身不處理為理由消除該事件。
這是 [ADR-0003](../adr/0003-decisions.md)／[IR §2 判定順序第 2 步](ir-vocabulary-1.0.md#單一判定順序)
對 PlayParameter Targets 的等價例外，不改寫 DSL，也不是一般的「只有一個候選就略過」。

略過的只有玩家輸入：權威端以穩定的候選順序代選合法目標，沿通常提交路徑保存目標決定與 E.targeted 歷史事實；
重播沿用已記錄的目標，不重新代選，也不偽裝成玩家回答。不能刪除選取事件來達成省略。

略過前須能證明等價：若條件仍可能在結算前改變，或有能力／規則查詢會觀察選取事件或歷史並因目標不同而改變處理，
就保留選擇；無法排除這類影響時亦同。不得透過是否顯示選擇畫面洩漏未公開資訊，
也不能因略過畫面繞過原有目標合法性檢查。
以上是規格要求，並不表示原型已有此最佳化。

## 驗收邊界

驗收須覆蓋 Q872 的觀察順序、Q1766 的階段順序（互換回合玩家）、隨機成本取消後的狀態等價，以及只有對手隱藏配置不同時的觀察不可區分。
移動測試要區分成功、取代、容量不足、再次換區及同名副本，並驗證進化仍同世代；只比較最終張數不足。
其他規則族的正反例及證據要求見[驗收規格](validation.md)。
