# 效果 DSL 規格

文件中的官方卡名、卡文及規則／Q&A 原文片段為引用，不在本專案授權內；
專案自有規格與解讀依 Apache-2.0。來源及版本定位方式見[文件引用說明](../quotations.md)。

版本：**1.0**（`schema: sve-author/1.0`），2026-09-28 採用。規則依據：綜合規則（CR）1.27.0。

原型引擎的有限能力與資源身分設定另見 [engine-rules/1](engine-rules-1.md)，
其語法權威在 `dsl/`；不把該格式當作 Effect DSL 1.0 已有的執行支援。

## 文件

| 文件 | 內容 |
| ------------------------------------ | -------------------------------------------------------------------------------- |
| [撰寫語法 1.0](author-syntax-1.0.md) | 人寫卡片 YAML 的唯一格式：能力頭、費用與目標、決定、表達式、動作原子、事件與歷史 |
| [IR 詞彙 1.0](ir-vocabulary-1.0.md) | 撰寫語法降低後的有型別 IR：型別、決定、捕捉、receipt、事件、持續效果、裁定型別 |

兩份的關係：作者只寫**撰寫語法**；載入時經語法檢查、巨集展開，降低成 **IR**，再做引擎 capability 檢查。
撰寫構造以 `A.*` 標示，IR 元素以 `I.*`、`K.*`、`L.*`、`E.*` 等標示，穩定 ID 不重用給不同語義。
撰寫語法的每個構造都說明降低到哪些 IR 元素；IR 詞彙不另設撰寫文法。

這兩份是規格，不是實作。正式 JSON Schema 會放在 `dsl/`，完成後由它作為語法的唯一機器權威；
Schema 與規格不一致時要修到一致，不能讓任一邊默默降級。

文中的 GAP 家族 ID（`GAP-A-nnn`、`GAP-S-nnn`）與句型 ID（`T…`）來自設計期的全卡句型分類，目前只作定位用；產生句型索引的工具之後會移進 `carddb`，隨卡表建置一起發布，屆時這些 ID 才能在 repo 內查到對應的卡片與能力行。

## 裁定

需要依綜合規則或 Q&A 才能決定的判讀登錄在 `authored/rules/rulings/`（`R-0001`…）。
IR §0 列出各裁定對應的 IR 元素與證據強度。`strength: inferred` 表示本專案解讀，
輔助模式提示時必須說明；不存決定者；裁定日期以頂層 `decided_on` 保留。

R-0006 已於 2026-10-09 經官方確認採路線 B（`official`）：spell 本文與チョイス選項費用是打出時的可選追加費用。先決定模式、目標、X 與各組是否支付，合計付款在 play 事件之前，效果依卡面順序結算；不支付的選項不適用效果，選擇支付卻付不起則取消打出。官方確認只登錄結論。

## 如何引用

- 引用規格：寫文件與版本，例如「撰寫語法 1.0 §4」「IR 詞彙 1.0 §7」
- 引用構造或元素：用穩定 ID，例如 `A.act.move`、`I.install-effect`、`E.stat-change`
- 引用決定理由：用 ADR 編號，例如「見 ADR-0008」
- 引用判讀：用裁定 ID，例如「依 R-0009」；卡片 meta 的 `rulings` 只列裁定 ID，不直接貼 Q&A

## 版本規則

依 [ADR-0010](../adr/0010-version-meta.md)：次版只能相容新增（舊資料不用改、降低語義不變）；
不相容的 IR 或既有語法語義變更要升主版。有效版本的規格與 Schema 同步維護；退役格式不在現行文件保留全文，歷史由 Git 查閱。
