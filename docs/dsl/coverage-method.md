# DSL 全卡覆蓋盤點方法

這份說明怎麼估計「全卡表中有多少卡能用效果 DSL 表達」，以及缺口怎麼分類。
D 階段對原型文法 `astra/1` 做過一次盤點；當時的比例與張數是那份卡表快照與那個文法的**快照數據，不保留**，
要知道現況就依本文方法重跑。

## 計數單位與輸入

- 單位是**一個印刷卡號**：該卡所有卡面的 `faces[].text` 加上所有 `faces[].sections[]`，都能表達才算
- 不刪除 token 定義、背面或括號內容；引用 token 定義的母卡也算受影響
- 同名重印各算一張，所以張數不代表不同設計的種類數；另外記錄完整能力文字去重後的數量作參考
- 輸入是固定版號的卡表快照；盤點結果要記下快照的 SHA-256，數字才能重現

## 分類

| 分類 | 判準 |
| --- | --- |
| **S** 現有結構可表達 | 能用 DSL 既有的構造與已定義的規則概念組成；不表示已有 YAML 或引擎支援 |
| **D** 需補領域定義 | 構造形狀足夠，但計數器 ID、事件內容或歷史查詢等名稱與語義還要正式登錄 |
| **G** 結構缺口 | 需要新增動作、宣告、值域或集合約束，才能保留原規則的付款、決定點與事件語義 |

判斷 G 類的標準是「DSL 能不能原生保存單次決定的語義」，不是「用冗長寫法模擬得出來」。
例如把「一次選出總費用不超過 N 的集合」拆成多次單選，會把一次決定變成多次有序決定，仍算缺口。

## 步驟

1. **基線**：所有能力欄皆空的卡（由共通規則處理，不需要卡片程式），以及已撰寫並審查過程式的卡
2. **已知缺口掃描**：用每個缺口家族的代表句型（正規表示式）掃全卡表，列出命中的卡號。
   正規表示式只能找出下限，不能證明沒有同義漏網；命中也要人工確認
3. **抽樣**：從「全卡表 − 基線 − 已知缺口」的剩餘母體，以固定前綴加卡號的 SHA-256 排序取前 n 張，
   逐張閱讀全部卡面與 sections，分成 S／D／G。樣本在開始審閱前固定，之後新增的掃描規則不回頭改樣本
4. **估計**：`(基線張數 + 剩餘母體 × 樣本 S 比例) / 全卡張數` 為保守點估計；
   `(全卡張數 − 已知 G 類張數) / 全卡張數` 為只排除已知缺口的上限。
   樣本比例可套 Wilson 區間展示不確定程度，但那**不是**語義覆蓋率的正式信賴區間
   （抽樣是固定雜湊的近似隨機、重印彼此相關、審閱者通常只有一位）

真正的完成度最後以逐卡程式、裁定與規則測試為準，不以這個估計為準。
要提高估計的可信度：先補領域型別登錄，由第二位審查者覆核樣本與缺口清單，再依獨立能力文字與最新卡包分層抽樣。

## `astra/1` 時期的缺口家族與 DSL 1.0 的對應

D 階段盤點找到的 G 類缺口，DSL 1.0 規格在**構造層級**都有對應：規格定義了可以寫的形狀，
不代表每種語義（例如同一規則多個來源如何合成）已定案，也不代表程式已實作。
引擎目前仍讀 `astra/1`，見[引擎現況](../sim/engine-status.md)。

| 缺口 | 代表句型 | DSL 1.0 構造 |
| --- | --- | --- |
| G1 效果中打出卡片 | 「コストを0にしてプレイする」「エボルヴデッキ…プレイしてよい」 | `play_card`（`I.play-card`） |
| G2 打出既有能力 | 「能力1つをプレイする」 | `play_ability`（`I.play-ability`） |
| G3 選出集合的總費用上限 | 「合計が…以下…探し」「見る。その中から…合計が」 | 選擇的 `cost_sum_le` 等集合約束 |
| G4 規則查詢的持續改寫 | 「何回でも」、SC 的計數方式、「カウンター…まで置ける」 | `rule_override`、`unlimited_evolve` |
| G5 非傷害事件的取代 | 「場から墓場に置かれる際、代わりに」 | `banish_instead` |
| G6 結算中宣告任意數字 | 「好きな数…指定する」 | `declare`（`kind: number`） |
| G7 從非通常區域打出的許可 | 「墓場からプレイできる」「消滅領域のカードをプレイできる」 | `play_permission` |

D 類（需補領域定義）當時有三組：新計數器的穩定 ID、UB 發動事件與歷史、融合的發起來源。

### `astra/1` 時期仍未解的六張

D 階段第一次盤點找到的 G 類缺口，到第二次封存時大多已在 `astra/1` 取得語法對應（不是逐張執行驗證），
只剩下列六張仍缺規則接口：

| 卡號 | 缺口 |
| --- | --- |
| BP02-035、BP02-036、BP02-SL07、BP02-SL08 | 改變スペルチェイン的計數方式（SC 計數提供者） |
| CP04-115、CP04-P87 | 計數器的放置上限 |

DSL 1.0 的 `rule_override`（`L.rule-modifier` 的 `SpellChainPopulation`、`CounterCap`）有對應的構造，
但同一規則多個來源的合成與依存在 [ADR-0008](../adr/0008-continuous.md) 仍未決，引擎也沒有實作。
這六張要用現行的 schema 與程式重新覆核，在那之前視為已知缺口。

## 工具

D 階段的盤點腳本、完整掃描規則、樣本鹽值與人工審閱表都沒有隨 repo 保留，舊數字無法重現。
上面的步驟與代表句型只能用來啟動一次**新的**盤點；開始前要先固定：卡表快照的 SHA-256、
完整的掃描規則、樣本的鹽值與數量，以及人工分類表的格式，並把它們與結果一起保存。

DSL 1.0 改用全卡句型分類（`GAP-A-nnn`、`GAP-S-nnn`、句型 ID `T…`）定位缺口；
產生句型索引的工具之後會移進 `carddb`（見 [docs/dsl/README.md](README.md)），屆時以它作為可重跑的盤點依據。
