# DSL 證據與驗收

語法可寫、IR 已定義、載入通過及執行驗收分別記錄；設計涵蓋預估或每族一個例子，不能證明全族已通過。
測試釘住輸入、規則版本、卡表快照與裁定版本，並記 hash。行覆蓋率是漏測提示，不能代替規則斷言。

## 分層檢查

語法層拒絕未知／重複欄位、非法 scope／capture／payload 與缺 capability；lowering 比較 inline 與巨集，巨集不得增加輸入點或改時點；執行層至少覆蓋各族正反局面。
巨集資格及逐用途 reviewed／verified 依[撰寫語法 §10](author-syntax-1.0.md#10-巨集規範)，不以頻次或共用存放直接授予資格。

M0 是核心規則局面基準，每 case 逐項 assert、任一失敗返回非零；M1 是已知問題與跨構造回歸，修復須留下可反覆執行的斷言，適合的探針轉成性質測試。
兩者是測試責任名稱，不代表引擎整合驗收已通過。測試須斷言事件數、順序、身分與可見性，不能只用整張 golden 或審核者意見一致替代。

## 證據失效

來源、裁定或巨集改動須反查受影響能力重驗；舊測試結果保存版本，不能當作新版 verified。
不以目前實作自動反寫測試期望；結論有爭議時標 disputed。重要規則用 mutation 驗證斷言能抓到錯誤。
專案推定的測試通過不會升為 official，期望須與採用的裁定版本綁定。
