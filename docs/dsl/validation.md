# DSL 證據與驗收

語法可寫、IR 已定義、載入通過及執行驗收分別記錄；設計涵蓋預估或每族一個例子，不能證明全族已通過。
測試以卡文及採用裁定的行為斷言驗證結果；不新增 runner／case hash、verification JSON 或結果 DB。行覆蓋率不能代替規則斷言。

## 分層檢查

語法層拒絕未知／重複欄位、非法 scope／capture／payload 與缺 capability；lowering 保留輸入點與時點；執行測試依實際語義差異選案例，不規定每卡固定數量。
輕量／共用本體與審查責任依[常見效果作者流程](common-family-authoring.md)，測試過不冒稱來源等價或官方證據。

M0 是核心規則局面基準，每 case 逐項 assert、任一失敗返回非零；M1 是已知問題與跨構造回歸，修復須留下可反覆執行的斷言，適合的探針轉成性質測試。
兩者是測試責任名稱，不代表引擎整合驗收已通過。測試須斷言事件數、順序、身分與可見性，不能只用整張 golden 或審核者意見一致替代。

## 證據失效

來源、裁定或本體改動跑受影響行為測試；完整回歸交 CI。舊審核保留紀錄，不以過期 metadata 阻擋無關卡。
不以目前實作自動反寫測試期望；結論有爭議時標 disputed。
專案推定的測試通過不會升為 official，期望須與採用的裁定版本綁定。
