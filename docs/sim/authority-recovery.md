# typed 對局的版本與權威恢復契約

本頁整理 typed 入口對外定版前必須具備的版本、保存責任與恢復驗收。
公開程式的承載依 [ADR-0019](../adr/0019-publish-typed-ir.md)，
權威與觀看資料的分界依 [ADR-0001](../adr/0001-engine-skeleton.md)；
不新增 wire Schema、持久化 API 或 save 格式，也不代表線上恢復已實作。

## 公開程式與版本准入

公開程式包承載完整展開並通過 lowering 的 typed IR，由生產端負責編譯及來源驗證。
這項決定不改成由瀏覽器重新 lowering 作者 DSL。
公開程式是卡片的靜態邏輯；對局中的私有候選、receipt 值、隨機權威與續體仍留在權威端。

依 [DSL 承載契約 §7](../dsl/author-contract-1.0.md#7-公開-typed-ir-與引擎能力)及
[快照傳輸 §3.4](../schema/export/snapshot-transport.md#34-dsl-程式包與版本准入)：

- 傳輸 `4.0.0` 的 programs 附件必須存在，而且 `entries` 只能是 `[]`；非空整包拒收。
- 啟用非空程式包必須另升 format，至少 minor，明列 DSL／IR 的權威 Schema 映射、
  必要能力及最低 reader 版本；依傳輸 §1.1 判斷是否需要 major。不能改寫 `4.0.0` 的空集合。
- Schema、公開 IR 解釋、producer、reader、共用樣本及拒收案例須一起對齊。
  IR 良構、整卡能力准入和執行時的付款、世代、來源及揭露重驗各有責任，不能互相替代。

程式封套的 `dsl_version` 不凍結 Rust enum 或 serde 的布局。
非空版本須明列公開 IR 的實際 wire 解釋，不能直接把內部 `CardProgram` JSON 當成已定版的承載。

目前 [`SelectedEffects`](../../sim/engine/src/catalog/selection.rs)及
[`Game::from_selected_effects`](../../sim/engine/src/game/internal/card.rs)
是行程內的選用與整卡准入入口，不是非空公開程式包的 reader。
已准入的計畫或共享 `Arc` 也不是可持久化的公開 IR 版本。

## 必須保存什麼、由誰保存

依 [ADR-0010](../adr/0010-version-meta.md)，資料、規則與引擎的版本分開記錄。
下面是保存責任，不指定新的欄位名稱、儲存服務或保留期限。

| 輸入 | 生產與識別責任 | 權威宿主的保存責任 |
| --- | --- | --- |
| 卡表快照 | carddb 提供版號、manifest、內容 hash 及引用閉包；仍是唯一卡片資料權威 | 保留本局實際採用的精確快照及所需成員 bytes、地區與身分對照，不能用目前 active 取代 |
| 程式內容 | 程式生產端提供精確內容、來源／面序對應、完整依賴及其格式、Schema、能力要求 | 保留本局實際選用的完整程式與內容識別；重播不重新讀取已變動的 authored 檔再當作原程式 |
| 引擎與規則 | 引擎建置與規則發布端分別識別實際引擎 build、CR／裁定、規則名稱／稱號／token／keyword 等實際載入的規則資料、准入／驗證政策 | 固定本局使用的組合；相同卡文或套件版號不能代替精確內容識別，不能靜默換用較新版 |
| 初始局面 | 可信宿主決定本局初始化資料、席位與規則設定 | 保存未公開牌組、初始順序及其他必要私有配置，以及採用的卡表／程式選擇；玩家觀察無法補齊 |
| 權威決定 | 引擎驗證已認證席位、當前題目及其權威回答 | 按受理順序保存實際命令、題目對應與結果，包含 `Reverted`、`Cancelled`、`EngineFault`，不能只記成功落地的動作 |
| 隨機輸入 | 權威端產生並消耗隨機輸入 | 保存足以重現該局的私有初始輸入、演算法／取樣版本與命名空間；從中點續行還須重建流位置，不能只留公開骰值 |

manifest 的 `engine_support_target` 是快照的支援目標，允許全 null；
它不代替宿主記錄實際執行的引擎與規則組合。
內部 [`EngineIdentityInput`](../../sim/engine/src/catalog/rule_bindings.rs)
核對的是呼叫端精確快照的身分資料，也不提供上述完整恢復封套。

只有版號與 hash、卻取不到對應 bytes，仍不能恢復。
公開 CDN 只保留 current／previous 的窗口，依[回放保留邊界](../deployment/replays.md)；
承諾可恢復的宿主須在其承諾期間內另確保所需內容可取得。資料缺失、hash 不符或版本不支援時拒絕恢復，
不向 latest 補值。本契約不延長 CDN 的保留期，也不指定歸檔目的地。

## 現有行程內能力與恢復缺口

| 現有入口或資料 | 已有邊界 | 正式恢復仍須補足的責任 |
| --- | --- | --- |
| [`Game` 序列化](../../sim/engine/src/game.rs) | active execution、未解決 prepared play 及已載入 CardRuntime 均拒絕存檔 | typed 續體、准入計畫、待處理及必要權威中間狀態的持久化契約尚未提供；不能只存 `State` 假裝完整 |
| [`Random`](../../sim/engine/src/random.rs) | 有版本標記、seed、stream、完整 word position 的私有隨機狀態及固定向量測試 | 這不是整局 save；宿主仍須保存本局的隨機輸入來源，並驗證版本、抽樣與洗牌消耗順序 |
| [`Knowledge`](../../sim/engine/src/game/knowledge.rs) | 保存觀看者的知情範圍、代號及發號高水位；origin 回滾不能復活失效代號 | 恢復須重建同一辨識歷程，保留私有發號輸入與回滾高水位，不能從目前可見牌面重新猜代號 |
| [`input/submit_player`](../../sim/engine/src/game/player/pipeline.rs) | 行程內檢查題期、席位與回答；拒答不前進，受理結果沿既有回滾與續行 | `player_epoch` 與 `player_fault` 不序列化；跨程序的請求身分、受理位置及結果保存尚未形成 wire 契約 |
| [公開事件序列](player-events.md) | 每席已提交前綴、游標與發生時授權；`EventId` 屬於該行程內事件流 | journal 不序列化，現行恢復重建觀察基線、不延用舊 cursor；不能以事件序列重建權威或當作持久提交位置 |

上述拒存限制同樣涵蓋只載入空 typed 程式的情形，不能靠省略欄位繞過。
玩家的 `Observation`、`Input` 與公開事件即使全部留下，也沒有未公開配置、捕捉值及完整續體；
它們是對外投影，不是權威恢復輸入。恢復後仍按每席知情範圍投影，不公開私有隨機狀態或原始權威紀錄。

## 重播、重送與中斷的驗收條件

以下是後續正式 wire／持久化實作的驗收方案，尚不是已完成的 typed 恢復保證。
以同一精確輸入與版本的不中斷執行作對照，從初始化重播完整受理前綴；
若採權威狀態的中點存檔，結果仍須與從頭重播相同。只使用既有准入的合成案例與代表卡片，不藉恢復放寬能力。

| 案例 | 必須核對的結果 |
| --- | --- |
| 版本及內容錯配 | 各別替換卡表、程式、引擎／規則或隨機版本，刪除依賴或破壞 hash；拒收不支援／不相符的組合，不回退 latest 或原型 |
| 多題回答與候選順序 | 在 X、模式、目標、材料、付款及 Quick 等已有程序逐題重播；actor、purpose、候選內容及業務順序、題內選項代號與回答對應相同，不拿舊索引直接回答新候選 |
| 物件代號重現 | 在相同私有發號輸入與辨識歷程下比對兩席完整代號；持續辨識者維持連結，失知、洗牌、私有排序及公開中途失知後 origin 回滾均不能把舊代號接回新期間 |
| 查詢不影響恢復 | 同一命令序列分別零次與多次額外讀 `observe/input/events`；權威結果、隨機流位置、候選及代號不因讀取次數改變。事件內容、順序與關聯依各席授權一致；新事件流仍拒絕舊 `EventId` |
| 隨機與隱藏配置 | 在抽牌、洗牌、Look/Search、骰子及重擲前後中斷；重播保留實際隨機消耗。只換另一席的私有配置時，可見資料仍依原資訊邊界，不把完整隨機輸入送給玩家 |
| 行程內重複或錯誤提交 | 原題錯席、過期題期、越界／錯型回答不改狀態或 RNG；已受理題目的原 token 不可再次付款或新增事件。投降等不綁題目 token 的命令仍按各自既有規則核對 |
| 持久受理前中斷 | 沒有持久受理位置的請求不得假報已提交；恢復後若重新受理，只能造成一次權威前進 |
| 已持久受理、回覆前中斷 | 恢復辨認已受理前綴，不能因客戶端重送再執行一次。是否回送原結果或回過期拒答由正式 wire 定義，兩者都須驗證不重複付款、消耗隨機或發布事件 |
| 題目懸置與回滾 | 在付款前後、nested／pending／准入及重擲題中斷；重建完整續體與原回滾範圍，不丟掉 mode、額度、RNG、知識與已發布高水位。取消、整次 play 回滾與故障保持不同結果 |
| 已提交前綴、終局與故障 | 已提交事件不重發，未提交前綴不提早發布。終局／投降保留原提交語義；`EngineFault` 不可因重啟被清掉後繼續，也不改判規則敗北 |

現有[玩家管線測試](../../sim/engine/tests/internal_ir/player_pipeline.rs)、
[觀察測試](../../sim/engine/tests/internal_ir/player_observation.rs)、
[事件測試](../../sim/engine/tests/internal_ir/player_events.rs)與
[隨機向量測試](../../sim/engine/src/random/tests.rs)提供行程內的行為依據，
不等於上述跨程序驗收已執行。正式恢復測試還須檢查持久受理位置與對局／席位／題目的綁定；
重送、拒答及事件 cursor 的 wire 語義不能從 Rust 型別的 Debug 或 serde 形狀推定。

## 對外定版的工作邊界

後續公開程式包工作須完成格式／能力協商、權威 Schema 與 reader 的一致性及正反例，
保持 `4.0.0` 空包規則。後續玩家 wire 須定義認證席位、對局與題目身分、候選／代號編碼、
重送結果及事件流重新建立的規則；後續權威持久化須定義受理前綴與必要輸入的原子保存及恢復驗收。
三者不能共用一個「版本已相同」判斷代替各自的准入。

權威狀態的中點存檔只作可另評估的恢復加速：必須與同一版本的完整重播對照，
不能成為省略權威決定與隨機輸入的理由，也不能混入玩家封包。
目前不新增跨版相容 reader 或自動遷移；正式持久化格式、伺服器及 WASM 綁定另行實作。
儲存目的地、清理、保存期限與下載授權仍依[部署／回放邊界](../deployment/replays.md)，
不由本頁替代維護者對線上生命週期的確認。
