# 主要階段合法行動意圖

當 `Game::input(viewer)` 回傳 `QuestionShape::ActionWindow(MainActions)`，當席玩家可選
其中的意圖，使用 `Command::MainAction { token, intent, answer }` 提交。
其他玩家只取得等待摘要；不列其私有候選，也不執行當席意圖的預檢。

目前意圖包含攻擊、卡片打出、有效起動實例、正常進化與結束階段。完整需求見
[#1975](https://github.com/gbaian10/sve-kit/issues/1975)；不能據此宣稱已能完成一般對局。
其他 typed 決定仍依[玩家輸入契約](player-input.md)逐題作答。

## 意圖與參數

- `Attack`：一位攻擊者對應一個意圖，提供當席可觀察的卡片與合法目標範圍。
  攻擊者依自己場上位置排列，目標先列對手主戰者，再依對手場上位置列卡片。
  沒有合法目標的攻擊者不列意圖。答案是 `MainActionAnswer::Attack`，只能選一個目標。
- `Play`：從當席可識別且現有權限允許的手牌、EX、墓地或放逐區，開始正式打出。
  一張卡一個意圖，答案為 `None`；後續模式、目標、分配與付款仍由原宣告程序逐題詢問。
- `Activate`：一個有效起動實例一個意圖，包含持有者及觀看者獲授權的文字來源與行號。
  多個同定義實例各有當題選項；來源已離場時只保留原有授權記憶，不連到新隱藏位置。
  答案為 `None`，參數與成本依原程序詢問。
- `Evolve`：一個有效的印刷進化定義對應一個意圖；以 `MainActionAnswer::None` 開始，
  再用 `Command::Evolution` 回答逐題參數。進化牌各面依當席已知卡號、面、規則名稱與
  代號排列，每張實體與面各列一次，不列出進化牌與付款的所有組合。
- `EndPhase`：沒有尚未履行的攻擊義務時，列在清單最後；答案為
  `MainActionAnswer::None`。這是離開主要階段的唯一玩家命令入口。

目標分為 `AttackTarget::Leader(Viewer)` 與 `Card(ObjectHandle)`，卡片代號可連到同席
的 `observe`。`MainIntentId` 是當題局部的不透明選項代號，不含可讀的權威物件 ID；
題目失效或來源世代改變後不能重用。有效實例的權威鍵與實例 ID 留在引擎內；玩家只取得
當題的選項代號。意圖不展開目標、材料或其他待答集合的完整答案組合。

查詢不推進規則，不配置代號或權威實例，也不改題目序號、亂數、知識或事件。
攻擊預檢共用權威的攻擊資格與義務讀取器，只讀公開場面；對手隱藏手牌或牌庫的
牌面、排序與實體 ID 不影響意圖。宣告預檢可以使用當席已知的手牌、公開場面、資源、
計數、時點與使用額度。宣告準備在拋棄式副本建立來源與 AtPlay 捕捉，不執行付款、
本文或亂數動作，也不輸出捕捉值。已決定的固定成本共用既有的純成本讀取器；
EX 承接與付款報價使用正式結算區上下文，不能把目前手牌報價當作保證價格。

打出與起動意圖表示可以開始正式宣告。可證明無解的固定成本先排除；
滿場只在沒有交換、未定成本、追加或可選付款，且成本僅涉及資源或來源本身時排除，
其他情況保留宣告，由付款後的場容量檢查決定。
依賴尚未選定的模式、X、材料、交換或其他付款條件時，沿既有宣告程序驗答，
不以試跑未提交亂數猜測可行性。意圖不保證後續每個參數選擇都能完成付款；
之後付不起仍依規則回復。Quick 維持原有「成本可付、目標可選」的 domain 契約，
沒有因新增 main 入口而放寬。宣告準備目前每個候選各複製一次對局；
頻繁查詢的配置成本仍待量測，再評估固定讀取器可否避免副本。

## 提交與續行

提交重驗應答者、當題 token、選項代號、目前物件知識、目標範圍、來源世代與 main
時點，並由共用權威 primitive 重驗攻擊資格或結束義務。錯誤代號、過期題目或不屬於
意圖的答案回 `Rejected`，保留原題、狀態與亂數；對外結果不帶私有原因。

攻擊沿用原有橫置、攻擊計數、攻擊事件與誘發，再由玩家續行管線完成 pending、
明確 Quick Pass 與戰鬥。沒有 Quick 選項也仍出 Pass 題。戰鬥結算後重新取得 main
題目，原意圖代號失效。結束階段沿既有守護、Quick、棄牌與換回合程序。
打出與起動沿[正式宣告程序](../dsl/play-semantics.md#2-程序已打出與回復點)：先決選項、
目標、分配都先於完整付款，付款後才檢查場容量並形成 played。開始宣告前的準備錯誤
表示預檢與權威不一致，回 `EngineFault`；宣告開始後依規則判為非法則回 `Reverted`，
沿原 origin 回復並讓舊題失效。內部故障保留原有回復範圍與已外發序號高水位，
停止出題，不改判規則敗北。

新的玩家介面不要求宿主傳實體 ID 或組權威 JSON，也不呼叫舊 `legal()` 的完整組合枚舉。
原型入口仍凍結；共用攻擊與回合 primitive 的既有規則差異保留。

## 正常進化宣告

`QuestionShape::Evolution` 的用途都是 `PlayParameter`，依既有權威程序依序列出：

1. `Form`：恰選一個進化牌面，回傳當題不透明 `EvolutionFormId`。
2. `Materials`：若印刷費用需要材料，用原材料題的候選與數量上下限回答。
3. `Discard`：若印刷費用要棄手牌，用原棄牌題選自己的手牌。
4. `Payment`：PP 加零或一點 EP 必須等於調整後總額；SEP 可用且達既有時點時，
   可選擇另付一點 SEP 進行超進化。生命等固定印刷費用不另出選擇題。

進化意圖只用可用性、配對與 PP／EP 的純讀取器預檢；材料、棄牌及生命等沿正式宣告
重驗，不試付或讀取未提交亂數。付款報價沿原權威的 frame、play-start freeze 與成本調整。
自己可讀裏向進化牌組；非應答席只看等待摘要。候選不因對手隱藏牌面或實體 ID 改變。

選定 `Evolve` 意圖時，共用主要意圖提交器仍配置內部因果節點序號。
接受 Form、Materials 或 Discard 等中間選擇只改私有續行與題目序號，不付款、揭露或執行本文，也不保存整份對局副本。
最後付款由引擎把選定代號轉成既有程序的物件參照，重驗來源、進化牌與材料世代、
印刷資格、限次、費用及 EP／SEP 時點。付款成功後沿既有事件、誘發與自動續行管線。
付不起或規則判定非法時回復付款前權威狀態，清除宣告並回 `Reverted`；錯題、錯答或
過期代號回 `Rejected` 並保留原題。內部錯誤回復後持續 `EngineFault`。

正常進化與效果進化是不同的規則入口；此介面共用正常進化付款與事件程序，不借用
效果進化來略過 PP、EP、SEP 或每回合限次。所有代號與續行仍只供行程內使用，沒有封包
序列化或恢復格式承諾。
