# 規則引擎現況與已知限制

`sim/engine`（crate `sve-engine`）目前是 D 階段留下、經 M0 修正的**原型**，不是正式引擎。
這份文件記錄它現在能做什麼、還不能做什麼，以及哪些限制尚未重新確認。

- 逐項的錯誤、預期結果與處理狀態：[M0／M1 已知錯清單](../m0/known-errors.md)
- 載入期會拒絕哪些 YAML、哪些構造還抓不到：[載入期拒絕的 YAML](../m0/rejected-yaml.md)
- 效果 DSL 的正式規格：[docs/dsl/](../dsl/README.md)

標記「待確認」的項目是 D 階段第三次封存時記錄的限制，M0 之後沒有逐項重新驗證；
在補上測試或核對程式之前，不要當成已修好，也不要當成仍然成立。

## 對 DSL 的支援範圍

- 引擎讀的是 D 階段的原型文法 `astra/1`：`authored/effects/*.yaml` 與 `dsl/effects.schema.json` 都是這個版本。
  `astra/1` 的語法以該 Schema 為準，語義以引擎程式與測試為準；D 階段的原型設計說明不保留
- [DSL 1.0](../dsl/README.md)（`sve-author/1.0`）目前只有規格：還沒有對應的 JSON Schema、載入器或 IR，
  也還沒有卡片用它撰寫。引擎改讀 DSL 1.0 之前，本文件列的限制都是針對 `astra/1`
- Schema 通過不代表卡文正確，也不代表引擎能執行；能否執行以載入期檢查為準（見下一節）

## 載入期檢查

`Catalog` 載入 `authored/` 時，除了 JSON Schema，還用 `sim/engine/src/catalog/semantics.rs` 檢查每張卡：
未實作的 opcode、引擎不會發出的誘發事件、未知的讀值路徑、選擇器欄位、期間與參數，一律帶卡號與行號拒絕，
被拒絕的卡永不執行。D 階段「未知讀值可能回 null／0」「部分宣告可能被略過」的情況已由這項檢查取代（KE-15）。

仍有抓不到、會靜默不做的構造（例如選擇器的種族名或卡名拼錯、`bind` 名稱的作用域），
列在 [rejected-yaml.md〈尚未涵蓋〉](../m0/rejected-yaml.md)。

## 測試現況

- 共同題本 `tests/rules-scenarios/` 706 個局面全部通過，已知失敗清單 `docs/m0/known-failures.yaml` 為空
- G1 代表題組 41 個局面全部通過；回放、輔助與 AI 共同局面的檢查通過
- `authored/` 的載入結果必須與 `docs/m0/rejected-yaml.yaml` 完全相同（目前只有 BP10-T09 被拒絕）
- `cargo test --locked --workspace` 全部通過（需設定 `SVE_TEST_SNAPSHOT`，見 [sim/engine/README.md](../../sim/engine/README.md)）

題本通過只表示這些局面正確，不能推論任意卡片、初始狀態或組合都正確。

## 執行邊界

以下「未完成部分」是引擎目前明確拒絕或尚未實作的範圍。

| 領域 | 未完成部分 | 狀態 |
| --- | --- | --- |
| 動作原子 | `declare_name`、`swap` 沒有執行實作，載入期拒絕；`link_resource` 只能當費用，出現在本文會被拒絕 | 已核對（`semantics.rs`） |
| 選擇 | `draw`／`look` 的 `up_to` 載入期拒絕；`distinct_by` 只支援 `name`；`search.groups` 已依組別檢查（KE-12），其他分組搜尋參數是否都已執行 | 前兩項已核對；分組參數待確認 |
| 付款 | `pay.cost_selections` 只支援單一平坦集合；一般多組材料、成本中未列舉的輸入及任意混合成本規劃未完成；大型局面的複製開銷未量測 | 待確認 |
| 土／資源 | 通用的計數器合併不完整 | 待確認 |
| 持續效果層 | 沒有完整的 CR 10.9 層次與依存排序、進化前費用讀值、數值期限還原；靜態限次折扣不完整 | 待確認 |
| 授予能力 | 每副本使用次數、非場上區域、混合數值的未來期間拒絕；同指稱的不同起動能力拒絕執行 | 待確認 |
| 打出與進化 | 內層多個符合能力時不能選擇能力；同一節點多物件的效果進化拒絕；從任意非通常區域打出的列舉未全部接入 | 待確認 |
| 禁止與取代 | 禁止出牌及任意多重移動取代的順序不完整 | 待確認 |
| 傷害取代 | 靜態限次／期限、同指稱多份限次實例、多個依變動傷害量重查的取代拒絕；跨接受者共用額度未建模 | 待確認 |
| 延遲效果 | 只支援自己的結束階段、指定物件離場／入墓；任意時點、跨控制者的組合未完成 | 待確認 |
| 區域容量 | 場上上限固定為 5；取代後改向有限區域未一般化；跨玩家同一 EX 區的身分轉移拒絕 | 上限已核對（`rules.rs`、`legal.rs`）；其餘待確認 |
| 限次誘發 | 多名額聯合選取、沒有公共事件區分鍵、選定前另有輸入的情況明確拒絕 | 待確認 |
| 資源回收 | 所有資源種類組合的回收未全面驗證 | 待確認 |
| 開局 | 不驗牌組構築合法性（KE-21，屬建牌器範圍）；匿名 filler 的無腳本洗牌拒絕；所有開始時能力未驗證 | 構築檢查已核對；其餘待確認 |
| 物件身分 | 戰鬥及所有中間綁定尚未一律使用帶世代的參照 | 待確認 |
| 結果紀錄（receipt） | 巢狀 `if_done` 沒有統一的完成量模型 | 待確認 |
| 時點讀值 | `at: play-start／resolution-start` 找不到凍結值時退回讀目前值（KE-17） | 未修，見已知錯清單 |

## AI

- 根節點確定化取樣（profile 的 `samples`，目前三個 profile 為 32）加固定啟發式延伸，
  展望到當回合、最多 128 個決定深度（已核對 `ai.rs`）。不是完整的 IS-MCTS，沒有對手策略學習或跨回合價值
- Rust 只載入 `profiles.yaml` 列出的三個 profile（`sim/engine/profiles/`）；
  [docs/ai/](../ai/profile.schema.json) 的 v2 profile 是未實作的設計，現行載入器不接受
- 沒有公開牌表時，對手先驗只含可模擬的卡；構築副本上限是簡化啟發式（待確認）
- `Game` 深複製的成本隨狀態線性成長，只有 `Catalog` 以 `Arc` 共用；還不適合大量搜尋

## 回放、輔助與資訊邊界

- 玩家投影不送出未公開手牌或背面起始護符的固定 ID；裁判視角與存檔含秘密，不能當一般封包傳送
- 回放保存完整 `Game` 快照，沒有持久化或差量壓縮；輔助模式只有手動攻擊、生命設定與兩層對齊
- 沒有真實網路、權限層、UI、不可信存檔的完整驗證或版本遷移；digest 尚未綁定 `Catalog` 內容指紋
- 以上為第三次封存時的敘述，待確認

## 建置目標

函式庫可用 `--no-default-features` 編譯到 `wasm32-unknown-unknown`；
還沒有 JS 綁定、瀏覽器宿主與計時驗證（待確認）。
