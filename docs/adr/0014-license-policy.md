# ADR-0014：程式與資料的路徑授權及第三方內容排除

狀態：已採用（2026-10-03）。頂層授權政策已由 [PR #236](https://github.com/gbaian10/sve-kit/pull/236) 合併，本 ADR 記錄該決定。

## 背景

sve-kit 包含 Python 卡表工具、Rust 引擎、Web 前端、可執行效果規則、人工採納資料與設計文件。這些路徑也可能包含官方卡名、來源引文、翻譯與圖像，不能因放在同一個 repository 就視為同一權利人的作品。

幾乎全部程式與資料由 AI 模型在維護者指示下產生。是否存在足夠的人類創作、可主張的權利範圍，依實際貢獻及法域而異；使用工具、核可與 commit 身分不能自行創造著作權。公開授權必須只涵蓋我們實際有權處分的部分，也要讓外部貢獻者能知道自己的提交適用哪些條款。

## 決定

2026-10-09 [#476](https://github.com/gbaian10/sve-kit/issues/476) 落地註記（以下原文為歷史決定）：Apache 路徑精確承接至 `authored/rules/effects/`、`authored/rules/keywords.yaml`、`authored/rules/engine/`；`authored/rules/rulings/` 仍屬原 CC0 範圍與引文例外，原授權決定不變。

程式採 Apache-2.0。`carddb/`、`sim/`、`dsl/`、`.github/`、`tests/`，以及可執行的 `authored/effects/`、`authored/keywords.yaml` 的自有貢獻適用此授權；設計文件、README 與其餘根目錄設定檔也採 Apache-2.0。

其餘 `authored/` 路徑的自有資料貢獻採 CC0-1.0，包括我們自己的翻譯與裁定說明，不強制對我們署名。官方原文、官方譯名及其他第三方內容的權利不受影響；這不是對整份衍生譯文或混合快照的自由利用許可。

[LICENSING.md](../../LICENSING.md) 以路徑表界定我們的貢獻，另具名列出第三方例外。定案題庫與裁定的來源引文保留出處並排除授權；官方圖片、角色裁切 logo、文件中的真實卡例及歷史舊版本的官方內容同樣排除。保留 Git 歷史不等於取得第三方授權。

外部提交按目標路徑的相同條款接受；翻譯與規則回報表單明示此原則，其他貢獻流程由 CONTRIBUTING 說明，不另要求簽署權利移轉合約。模型與 bot 的 trailers 記錄工作與審查，不代表法律作者或權利認證。

根 LICENSE 使用 Apache 標準全文，README 的醒目摘要與 LICENSING 補充資料及官方內容的邊界。法律條文不自行改寫，NOTICE 僅保留必要歸屬；完整範圍與第三方說明集中於 LICENSING，避免重複且難以同步的規則。

## 考慮過但沒選的方案

- MIT：簡短且容許廣泛使用，但沒有 Apache 的明文專利安排，本案沒有因此增加另一套程式授權的需求。
- MPL-2.0：散布修改過的受涵蓋檔案時有原始碼要求，但單純託管服務通常不觸發，不能達成防止閉源線上改作的目標。
- AGPL-3.0：對修改版的網路互動有對應原始碼提供義務；本案接受他人閉源與商業利用自有程式，選擇較容易嵌入和貢獻的 Apache。官方素材的使用限制另論，不能靠 AGPL 取得許可。
- 資料或翻譯用 CC BY／CC BY-SA：要求署名或改作回饋，但我們的事實資料、AI 貢獻與源自官方的翻譯不適合再宣稱完整控制；選擇放棄自己能處分的資料權利，原作權利不動。
- ODbL：資料庫的分享與回饋條件增加管理成本，不能處分單一內容的上游權利，暫無採用必要。
- 程式 Apache、資料 CC0、文件 CC BY 的三種授權：文件含規格和程式片段，跟隨 Apache 可減少邊界與維護成本。
- 依欄位內容性質決定自有授權：外部貢獻者難以操作，改採明確路徑表；第三方排除仍保留必要的欄位提示。
- 只有部分檔案的自動授權標示設定：不能代表全樹已檢查；暫以明確範圍文件落地，未來有完整覆蓋與持續檢查後再引入。

## 後果

Apache 容許閉源與商業改作，已合法釋出的舊版不能因後續改變授權而收回；外部作者保留自己的權利。CC0 不要求我們的資料使用者署名，但來源記錄仍有助於查核，不能代替許可。

第三方軟體、字型與圖示保留原條款，發布時按實際包含元件附告示。軟體產生的快照、圖片或音訊不自動繼承產生器授權；不得把混合產物整體標成 Apache 或 CC0。官方內容的排除與網站聲明不會補足上游許可。
