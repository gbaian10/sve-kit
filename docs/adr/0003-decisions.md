# ADR-0003：四種決定與單一輸入點判定

狀態：已採用（2026-09-28）。規則版本：CR 1.27.0。

## 背景

BP17-SL28 的 Q2294 允許進化牌庫只有一張符合者時仍選模式 3 而什麼也不發生；「候選不足就跳過整個決定」不能當普遍規則。BP13-043 的 Q1766 要雙方先指定，再交付，交付前提只保護交付步驟。BP08-011 的 Q1060 又禁止只有一個目標時打出，不能用結算「盡可能做」放寬打出需求。

CR 10.6.2.2–.5 規定打出參數，10.6.2.8 規定本文，5.18.2.1 的模式「最多 N」是至少一個，與 1.3.5 的普通最多零到 N 不同。這些差別會影響使用者操作、付款、資訊與重播。

## 決定

採 PlayParameter、ResolutionChoice、RuleChoice、QuickWindow 四型。チョイス屬 PlayParameter；本文 either 與普通 choose 屬 ResolutionChoice。異玩家選擇或內層打出即使由協定的結算輸入承載，仍保留真正的決定類型與 execution。

輸入判斷共用一套程序：先判明示 P.start 或原定強制零單位，再判打出必要參數與規則程序；QuickWindow 固定保留；已開始而要求選擇的指示即使僅一個合法答案、空集合或 Decline 仍保留輸入。這是專案協定選擇，不把每個輸入畫面都冒稱 CR 必須顯示。may、min=0、不能做是三種不同結果；材料選擇和付不付合併 compound answer，不額外詢問一次。

變身按 CR 5.17.1 降為消滅，再以實際消滅數建立 token。BP08-011 用 TokenAllocation，完整成功各一張（Q1061），不建立原卡→模板的 Map。分配在新建步驟 ResolutionChoice（由 CR 推得，generalized）；僅成功消滅一張時由 actor 在兩模板選一種、每種至多一張（R-0013，`strength: inferred`），零張不建立。新建容量程序另處理，不能把場地容量反推成消滅數。

## 考慮過的選項

| 選項                 | 為何不採／採用代價                                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 唯一候選即自動操作   | 不能區分 Q2294 可不執行與真正強制動作；若輸入存在性依私有候選變化，還會外洩資訊。特定無選擇規則程序可略過，不能擴成通則。 |
| 所有選擇都在打出時問 | BP08-011 還不知道實際消滅數，會預先決定失敗成員的 token；either 也錯置。                                                  |
| 所有選擇都延到結算   | Q1060 要求先有兩個目標才能打出；這會讓非法 play 先付款、計 UB 或進歷史。                                                  |
| 只有 yes/no 輸入     | 材料與選擇分開會增加不存在的反悔點；symbolic domain 可表達有上限／無上限數量而不用枚舉所有答案。                          |

## 後果

DecisionPointId、actor、visibility、execution、occurrence 必須可稽核；私有候選只給 chooser。驗收至少包括 Q2294 的不足候選、Q1766 的先指定後交付、Q1060 的打出拒絕與變身成功 0／1／2 張三種結果。

## 未決事項

變身只成功一張的分配已採用為專案解讀（R-0013），標 `strength: inferred`；官方 Q1061 只直接證明完整成功情況，後續有直接證據可修正。相同時間戳效果排序採 RuleChoice，須保留獨立程序與重播，不併成卡片本文選擇；兩者的引擎驗收仍待實作。
