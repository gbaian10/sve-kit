# ADR-0009：PlayerRef 與 PlayerSet 分型

狀態：已採用（2026-09-28）。規則版本：CR 1.27.0。

## 背景

BP13-043 的 Q1766 要回合玩家先指定，非回合玩家看見指定後再指定，之後才各交付。BP06-P31 的 Q872 則先雙方看牌、依序選擇出場、再雙方處理剩餘牌。若每個玩家各跑完整本文再換人，觀察時點和卡片所在地都不同。

二人局中「相手」只有一位，容易讓 IR 全寫單一 player_id；但 BP05-006 明示某一對手做模式選擇，其他卡的「相手リーダーすべて」則保留集合量詞。CR 1.1.1、1.3.4.1、3.1、5.22 分別界定玩家、同時處理與控制權，不能從二席巧合推導未來多人規則。

## 決定

PlayerRef 是單一確定席位；PlayerSet 帶 relation、relative_to、cardinality、text_quantifier。二席的 Opponents 在單人 actor／draw 等位置以 RequireOne 轉換，檢查恰一人，不取陣列首項，也不新增玩家選擇。卡文明示選一人仍保留選擇，不能因二席只有一候選而消失。

各玩家程序用 K.each-player.stages，按階段橫跨玩家：非選擇步驟同時，有選擇者回合玩家先；卡文特定順序優先。階段是否包含內部容量／守護等選擇也須計入，不能只看外層節點名稱。無法證明 nonchoice 時拒絕含糊 lowering。

actor、owner、controller、destination owner 分開。給對手場建立 token 的執行者不必是接收者；leader_of／master_of 依目前控制者、離場依法 LKI，owner_of 表示所有者。多領袖傷害保留同批事實，不用遍歷玩家把同時改成先後。

## 考慮過的選項

| 選項                                   | 為何不採／採用代價                                                                  |
| -------------------------------------- | ----------------------------------------------------------------------------------- |
| 全部只用 PlayerRef                     | 丟失「所有對手」與「一位對手」區別；日後多人化只能回頭重讀每張原文。                |
| 全部用陣列，需單值時取 first           | 陣列順序不是玩家選擇或規則順序；會偷偷製造多人勝敗及費用分配語義。                  |
| 每玩家整段完成再換人                   | Q1766 的第一人先交付會改變第二人指定候選，Q872 的剩餘牌也提早處理，與官方步驟不同。 |
| 一見 PlayerSet 就禁止二人 runtime 載入 | 會不必要地拒絕大量正常的全體效果。保留集合型別，再以二席合法轉換即可。              |

## 後果

語法可保留多人量詞，runtime 仍只承諾二席。決定可見性按 actor 驗證，資訊投影更易稽核。驗收須以兩方交換回合玩家重跑 Q1766／Q872，另測只有一對手時不額外增加 RequireOne 輸入。

## 未決事項

多人回合排程、敗者移除、攻擊及技能選擇需另一份規格；PlayerSet 的存在不表示多人對局已支援。多席而無已登錄規則的 lowering 明確拒絕。
