# ADR-0021：翻譯採術語葉、文法形式、有限名詞片語與整行句框架

狀態：提議（2026-10-10），待獨立審核與維護者核可；不代表相依實作已驗收。
需求與已定方向見 [#495](https://github.com/gbaian10/sve-kit/issues/495)；欄位契約見[四層翻譯](../schema/domains/four-layer-translation.md)。
本決定延續 [ADR-0018](0018-translation-validation.md) 的當前值與必要自動檢查原則，不恢復逐詞核可或翻譯證據層。

## 背景

固定整行模板只把數字、卡名及部分記號抽成參數，區域、特性及其他概念常藏在譯文固定字中。
改譯名要逐模板修字，量詞及方位形式也分散；加粗缺乏概念位置，只靠事後搜尋會誤中卡名內的同字。
DSL 若另從原文抽一次玩家、區域與數量，兩邊便可能使用不同值或語義角色。

單純切得更細不會解決這些問題。整行可以包含費用、分支、先行詞、動作結果及選定時的捕捉；
拆成獨立句子會把這些關係推到卡片層的組裝接口。共用率不能代替來源與語義正確性。
既有模板、模板 ID 與譯文可以重建，遷移成本不作反對新模型的理由。

## 決定

以同一份已驗的來源綁定供翻譯、加粗及 DSL 使用，分成四層：

| 層 | 責任與界線 |
| --- | --- |
| 術語葉與有型別值 | 保存概念／詞彙身分、數量、角色與合法域；每次引用有自己的來源位置 |
| 有限文法形式 | 以基礎名稱和語境產生量詞、在／到／從、方位、關鍵字括號及動詞融合；形式不執行遊戲動作 |
| 封閉名詞片語 | 組合既有葉引用、容許部分覆蓋；未涵蓋修飾留在框架的固定譯句與葉引用，不造 opaque 字串槽 |
| 整行句框架 | 保留固定動作、條件、否定、任意、時點、能力 scope 及跨句關係；所有頻次都有框架 |

四項必要條件如下。

1. NP 是有限且可部分覆蓋的呈現層，不能等所有日文修飾都解析完成才翻譯。提高 NP 覆蓋不改 frame ID。
2. 量詞必須依計數物、所在區域集合與數量角色查表並驗回原文單位。EX 區代幣從者的体、跨區聯集的枚、護符的つ／枚及主戰者的人分別有具名規則；原文單位表與中文風格表分開。
3. 框架維持整行，語義身分包含 canonical source、葉槽型別／角色／域、semantic_variant、normalizer 版本與投影分類。打出時目標和結算時選擇、費用和效果等差異必須分 ID；中文形式、NP 分組與加粗不入身分。DSL 的 ports／scopes 描述由獨立依賴鍵追蹤；描述調整須重驗相依 DSL，來源語義不變時不使翻譯重鍵。
4. 形式不只加方位字，還包含在／到／從與「加入手牌」「回到手牌」等動詞融合。名稱由同一選詞引用產生，不能在每個形式抄一份。

SourceBinding 精確釘住 owner、欄位、段落、來源 hash、葉值和 raw／canonical 位置；
正規化保留單位、別名、省略及 Unicode 轉換的 trace。NP 不再抽值，DSL 不從中文 target 猜動作。
框架相同不代表不同區域或用途的完整規則等義；未解分類保持 pending，不當 no-op。

各頻次的框架都可保存有版本的 DSL 本體。1～2 張不同卡仍按逐卡標準接受獨立語義審核；
同一語義變體達三張不同卡（卡名＋是否進化；重印／異圖不累計）才滿足合格巨集的頻次條件，
仍須適用域、獨立審核與邊界測試。2→3 升級資格，不搬移本體。
正式資格條文由 [#497](https://github.com/gbaian10/sve-kit/issues/497) 修訂作者語法 §10；
本 ADR 不自行授予任何框架 reviewed／verified，也不改 DSL Schema。

繁中翻譯以日文為唯一一般來源：已確認同卡同面且 JP 來源有效，即使沒有 aligned 或已知日英效果不同，仍顯示 JP 依據的繁中。
日英段落不同取完整 JP 效果，不按 EN ordinal 拼接。移除翻譯入口 source_exception，保留區域差異對 DSL、機制及官方 counterpart 的限制。
真正沒有 JP 的純英文卡由 [#500](https://github.com/gbaian10/sve-kit/issues/500) 個別處理，不建立一般 EN parser。

## 考慮過的選項

| 選項 | 收益 | 取捨與結論 |
| --- | --- | --- |
| 只把整行改成句子粒度 | 可增加表面句子的重用 | 不解改名、量詞或加粗位置；多句作用域、費用與結果要另組裝。不採用作為這次改版方向 |
| 保留固定模板，只加單詞引用 | 集中譯名並取得概念位置 | 缺乏語境形式時，量詞仍綁死卡種、格與動詞融合散落模板；任意片語參數又會遮住葉值。不足以承擔共同資料契約 |
| 四層且保留整行 | 概念、形式與值共用，逐位置加粗，DSL 取得同一 typed binding | 要維護有限文法、單位表及 scope 邊界；以部分覆蓋、封閉結構及反例限制複雜度。採此方向 |

## 後果

normalizer、模板 schema、renderer、DB、位置投影與 reader 需要協同替換；不保留永久舊格式相容分支。
先完成一條 authored→DB→快照→Web 的垂直切片，驗部分 NP、單位、跨句值與位置，再整批重建譯文與引用。
JP 翻譯基線不以 NP 全覆蓋或全部 DSL 本體完成為前置。

舊模板到新 frame 為多對多，以來源 occurrence、語義變體及適用域映射。
每個裁定引用必須是唯一且不擴域的 resolved，或保留原因及候選的 pending；不繼承舊審核資格，不留假有效懸空引用。
永久卡片身分、配號游標、人工日英對應、來源歸檔原 bytes 與官方／專案譯文的授權分離不變。

固定案例與欄位表只是可審閱的設計；normalizer 正確性、中文自然度、公開格式、容量及實際引擎行為仍須各自驗收。
本 ADR 的實作合入前須完成維護者核可，不能用設計方向已選定取代對實際 ADR／PR 的審閱。
