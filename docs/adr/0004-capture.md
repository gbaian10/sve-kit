# ADR-0004：讀值捕捉與條件求值分離

狀態：已採用（2026-09-28）。規則版本：CR 1.27.0。

## 背景

BP12-109 的 Q1708 指定防止傷害只影響能力打出時已在場的對方從者；Q1709 進一步要求這些來源離場後，其 lastword 傷害仍受限制。反之 DSD01b-001 的 Q1246 中兩個 lastword 依序結算，第二個要看到第一個剛建立的 token。若把所有讀值凍在能力開始，第二個就會重建不該建立的 token。

R-0009 引 Q940 說明兩次分開的傷害各自誘發、各讀那次傷害值，不能相加；Q852／Q2418 說明後結算條件可由先結算效果改成成立。CR 10.7 與 10.6.2.8.2 因而需要將誘發事件、讀值時點、條件求值三者分離。

## 決定

每個 read 登錄型別、合法 capture、上下文及可見性。Live 於使用步驟讀；AtPlay、AtResolution、AtSelection、AtEvent 各帶明確 scope。事件值 AtEvent 不因條件晚判而變 Live；receipt 完成後固定，不增加第六種捕捉。SC／NC 的固定捕捉按各自規則登錄，不推廣到全部條件。

事件發生即依事件 filter、有效區和限次進待機，普通本文 if 到該段才判。R-0009 取代先前雙重條件檢查；狀態誘發保留自己的 latch。條件管段落／模式邊界，Q1245 證明不能做前句後立刻因新狀態轉去另一分支。

define 是純表達式別名，卡文 X 在每次使用點依 read 時點展開。同一指示重複讀用相同開始視圖，跨指示普通場面可改變。「那張卡的玩家」用目前 controller，離場依法 LKI；不一律鎖在選目標時。apply 通常捕捉指示開始的集合，BP12-109 明示 AtPlay；static 則動態求值。

## 考慮過的選項

| 選項                                 | 為何不採／採用代價                                                                             |
| ------------------------------------ | ---------------------------------------------------------------------------------------------- |
| 全部 Live                            | BP12-109 會錯誤涵蓋後來入場者；事件傷害值也可能改讀目前累積傷害，違反 Q940。                   |
| 整段在 resolution 入口凍結           | Q1246 第二個 lastword 應看到第一個已建 token；段落內會改變的 X 也不能只計一次。                |
| 依公開／隱藏區猜 capture             | 公開區仍可能是 Live、AtPlay 或 LKI；區域資訊無法取代卡文證據，也無法解釋 Q1709 的離場來源。    |
| 將 when 同時作誘發 filter 與本文條件 | 導致 Q852／Q2418 原本 false 後來 true 的能力根本不待機。明示 on 與 if 雖略長，但避免雙重解釋。 |

## 後果

遷移必須辨別事件限定和本文條件，不能只把 when 改鍵名。複合表達式每個 read 各帶捕捉資訊；原子欄位需提供足夠型別使錯時點可載入拒絕。驗收正反例包含先 false 後 true、先 true 後 false、事件值保持不變、BP12-109 新入場不受限。

## 未決事項

新卡若明示同段 X 固定，需新增有證據的 capture 定義；不能讓作者任意寫 at 覆蓋規則。快照共享與記憶體生命週期待效能量測，但不得改成讀目前同 ID 物件。
