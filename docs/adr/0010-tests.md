# ADR-0010：分層證據與測試閘門

狀態：已採用（2026-09-28）。規則版本：CR 1.27.0。

## 背景

BP08-011 的 YAML 可以合法解析，但仍可能錯在選目標不足也允許打出（Q1060）、建立兩張同 token（Q1061）或分配時點。CP04-P86／CP04-003 的 UB 計數同樣可寫出型別正確而違反 Q2391 的流程。BP13-SL16 的 Q1776 需要驗證未移動成員沒有 counter，單看最後總張數不夠。

CR 10.6、10.7、10.9 同時約束時點、待機、持續效果。語法、降低結果和實際執行各只能證明不同事情，不能用一個總 coverage 或人工「看起來合理」代替全部。

## 決定

分別記語法可寫、IR 已定義、載入通過、執行驗收。設計涵蓋預估只表示目前提出的構造預期能涵蓋某句型集合；每族一個例子不證明全族已通過。測試輸入、規則版本、快照與裁定版本固定並記 hash。

M0 為核心規則局面基準：每個 case 必須逐項 assert，任一失敗返回非零；M1 為已知問題與跨構造回歸：修復要有可反覆執行的斷言，探針能轉性質測試者轉為性質測試。這些名稱是測試階段，不依賴特定原型或私有題目。未取得實測證據不能宣告引擎整合驗收。

語法測未知／重複欄位、非法 scope／capture／payload、缺 capability；lowering 比較 inline 與巨集；執行至少每族正反局面。巨集需至少三個不同卡名、獨立審核與 0／無目標／大數值邊界，逐卡句型、參數、反向翻譯三項檢查才可 reviewed，實跑才可 verified。

| 高風險         | 必要斷言與可追溯依據                                                                                                                                                                           |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 打出參數／付款 | 目標先於費用；拒付／非法目標不計 UB（CR 10.6.2.3–.7、Q2467）                                                                                                                                   |
| 條件與捕捉     | false→true、true→false，事件值固定（Q940／Q2418／Q964）                                                                                                                                        |
| may、零與容量  | 不足仍保留可拒絕路径，部分成功不產生假 follow（Q2294／Q1776）                                                                                                                                  |
| 歷史與批次     | UB 外層可見但總數不重複（Q2391）；一次多接受者只誘發一次（Q2549）                                                                                                                              |
| 持續與入場     | 進化不算 +、超進化算（Q2758／Q2759）；initial posture 不另發 act（CR 10.9.3）                                                                                                                  |
| 推定邊界       | 變身只消滅一張、同指示攻體兩 facet、持續條件重算／到期、同 timestamp 排序、BP14-046 共用一次與 BP20-P65 選 0 皆已採用（R-0010～R-0015）；測試期望保留 `strength: inferred`，通過也不升官方證據 |
| 資訊           | 僅對手隱藏狀態不同時，未獲授權玩家的觀察不可區分（CR 4；Q872 的公開順序）                                                                                                                      |

## 考慮過的選項

| 選項                  | 為何不採／採用代價                                                                 |
| --------------------- | ---------------------------------------------------------------------------------- |
| 只看行覆蓋率門檻      | 即使執行過 UB 分支，也未必斷言外層可見且不重計；覆蓋率是漏測提示，不是規則證明。   |
| 只靠兩位審核者一致    | 可能共享同一錯誤讀法；需要用官方正反例與可執行斷言打破同源誤讀。                   |
| 只跑家族主例          | A-001 的不同 X 來源與時點不一定都由一張抽牌卡代表，參數跨度需要非主例抽驗。        |
| 所有卡只做快照 golden | 輸出變更時容易整批更新期望，無法說明對錯；需事件數、順序、身分與可見性等獨立斷言。 |

## 後果

來源／裁定／巨集變動要反查受影響能力重驗，失效證據仍保存舊版本。測試失敗不可自動以目前實作反寫預期；有爭議先登錄 disputed。重要規則增加 mutation，確認斷言真的捕捉錯誤。

## 未決事項

正式 runner、局面資料格式與效能測試門檻待實作。推定邊界的期望須隨採用的裁定版本保存；無官方結論時不能把一次測試通過升成 official。
