# ADR-0001：採用執行與資訊邊界骨架

狀態：已採用（2026-09-28）。規則版本：CR 1.27.0。

## 背景

引擎必須同時回答「遊戲真正發生什麼」與「某玩家依法可知道什麼」。兩者不是同一份資料。BP06-P31 的看牌流程，Q872 要求雙方先各看牌，再由回合玩家選擇出場，另一方可看見其公開結果後再決定；這不授權另一方看見尚在牌庫中的候選。BP03-088 的隨機捨牌成本，則要求引擎能重現隨機選取而不讓玩家先看結果後取消付款。CR 4 的區域可見性、10.6.2.5.4 的不能支付時回復、10.7 的待機與檢查時點共同約束架構。

BP13-043 與 Q1766 又要求「雙方指定→雙方交付」按階段處理。將每張卡實作成一次同步函式，或讓 UI 自行完成整段，會失去中途輸入、對手可見結果和規則檢查的邊界。架構選擇須能表達上述行為，而不是依某個卡包建立特例。

## 決定

採唯一 authoritative state，規則執行器以有型別 IR 驅動。決定描述與續體分開：前者描述 actor、合法 domain、可見性與 execution，後者只在 authority 保存待續步驟。玩家／AI 只取得 Observation 與其獲授權的 DecisionView，不取得完整 state 後自行忽略隱藏欄位。

規則動作、決定、RNG、歷史事實、觀察投影各有明確界面，但只有一套狀態提交管線。事件事實不是直接序列化到網路的封包；公開投影可省略或匿名化私有部分。卡表只引用有版號快照，不在引擎內建立第二份印刷資料。

付款取消必須能回復 state、RNG、事實、待機與使用額度。重播保存權威決定／隨機輸入的版本，觀察者重播仍須套相同可見性。未知 read、event、欄位或缺少 capability 在載入時附來源位置拒絕，不能走任意 callback。

## 考慮過的選項

| 選項                             | 為何不採／採用代價                                                                                         |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| UI 直接持有完整對局 state        | 實作快速，但 BP06-P31 看牌時可從封包讀到對手候選；即使畫面不顯示仍已洩漏。之後補 UI 遮罩無法回收已傳資訊。 |
| 每卡腳本自行暫停、續跑與提交     | 每個腳本都要重做 Q1766 的階段與 Q872 的可見性規則；錯誤難以由共同測試定位，也不能保證成本回復完整。        |
| 同時保留兩套引擎，以卡片選路徑   | 可重用舊程式，但待機、歷史與亂數會有兩個權威；混合卡片對局無法以一個規則順序解釋。                         |
| 有型別核心與單一觀察投影（採用） | 初期需要更多介面與續體程式碼；換得每個規則程序共用一次資訊審計與回復測試。                                 |

## 後果

任何新動作都必須定義 receipt、可見性與續體邊界。UI 和 AI 不因新增能力而擴大權限；能力來源與當事者資料可保留於 authority，僅投影規則允許的部分。驗收至少覆蓋 Q872 的雙方資訊順序、Q1766 的階段順序、隨機成本取消後與原狀態的等價性。

## 未決事項

續體的 Rust 表示、權威重播格式及 Observation 的匿名引用策略仍待實作量測；這些選擇不得改變決定順序或讓私有 ID 可被跨區追蹤。架構定案本身不代表規則局面已通過測試。
