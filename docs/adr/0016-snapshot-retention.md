# ADR-0016：公開卡圖只留最新、快照保留兩版

狀態：已採用（2026-10-04）。取代 snapshot-format 原 §4.1 的永久版本索引與永久資產閉包政策。

## 背景

原契約要求 R2 永久保存全部已發布快照及其圖片閉包，供未來對局重播或舊牌組讀回當年資料。
目前尚無正式發布，這些功能也未形成實際保留需求。維護者希望使用者看到最新卡圖，裁切更正後亦只需新圖，
不希望為假設的歷史用途保存多份 WebP；因此取消整條永久保留要求，不能再用它約束當前設計。

## 決定

公開卡圖只保留 current 圖片集合；依 [ADR-0015](0015-image-url-version.md) 覆寫固定 ID key，
previous metadata 中的舊圖片引用不構成保留舊 bytes 的理由。使用者接受新快照後必須切新圖 URL，不能 fallback 舊圖。

公開快照只保 current 與直接前一發布版 previous，首次 previous=null。
每個保留版本仍需完整 JSON／文字分片／清單／config／影像 metadata／programs／changes 及所列壓縮表示，
共同 hash 去重；內容定址 JSON 不覆寫，但輪替後可回收。「不可變」不代表「永久保存」。

版本入口採獨立 index_format=2 的 current／previous 索引，不維護永久 pages 或每代 index 歷史。
先驗新內容與圖片、最後條件切索引；提交後依同一 revision 邊界回收，不能刪到仍保留的共用 blob 或合法在途發布。
current 的 changes 描述 previous→current；previous 所引用的 changes blob 仍保留，
但其 from_data_version 只是標識，不遞迴要求第三版快照及資產。
落後多版的 client 直接取得 current，所需舊片被回收時亦重新取 current，不要求補歷史鏈。

對局重播及舊牌組的歷史資料還原留待實際開發時另設計。本機引擎確定性重播、來源重算與既有採納驗證不刪除，
也不因此提供公共歷史資產服務。永久 int_id、卡片入口 alias 與人工採納歷史不改；舊牌組仍以永久 ID 對目前資料定位。
來源 raw、PNG、manifest、inventory、封存批次與必要備份照來源歸檔契約保存，公開 WebP 回收不授權刪除它們。

文字 ID 碰撞檢查改用耐久的精簡 `(lang,short_id,full_digest)` 發布鍵索引，事件首次 data_version 用發布收據固定；
不能因 R2 只保兩版就遺失碰撞／首次發布證據，也不為此保存完整歷史快照。
完整保留及過渡契約見 [snapshot-format §4.1](../schema/snapshot-format.md#41-發布窗口圖片新鮮度與回收)。

## 考慮過的選項

| 選項 | 取捨 |
| --- | --- |
| 全部快照與圖片永久保留 | 能定位歷史內容，但為尚未開發的需求持續累積儲存與相容責任，不採用 |
| 快照永留、圖片只留最新 | 減少圖片容量，但仍承諾完整歷史文字及永久索引，超出目前需要 |
| 快照與圖片各留兩版 | 更新過渡完整，但舊圖片沒有保留需求；previous 的 metadata 可保留而圖片只取最新 |
| 全部只留最新 | 儲存最少，但缺少快照切換的前版過渡，故文字／metadata 保留兩版 |
| 快照兩版、圖片最新 | 採用；更新成本有界，需清理與 client 過期恢復流程 |

## 後果

舊 reader 不再保證總能在 CDN 找到相容歷史版，只能用 current／previous 的相容項或本機完整 active，否則更新程式。
離線裝置可暫用已下載資料並明示時效，不能宣稱已知最新圖；伺服器不為慢下載或本機 pin 無限延長窗口。
回收遵守來源、身分與公開產物的邊界；changes 不再被當作歷史快照 FK。
ADR-0001 的本機重播原則與 ADR-0013 的建置遷移證據仍成立，均不要求公開 CDN 永久保留。
