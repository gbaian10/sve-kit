# ADR-0008：持續效果、依存、取代與數值事件

狀態：已採用（2026-09-28）。規則版本：CR 1.27.0。

## 背景

BP21-P53／P54 的「體力增加時」不能只比較目前與上次顯示數字。Q2758 明說進化造成的基礎攻體增加不誘發，Q2759 明說超進化誘發；CR 12.2.4.1 正是在關聯進化牌後明示 +1/+1。BP11-P28 的 Q2075 對「攻擊力或體力增加」也確認超進化會誘發，但沒有直接回答一次指示的誘發次數。

CP04-PR22 的 Q2540 證明裝備事件所安裝的數值修正，在失去能力後仍保留；BP12-109 的 Q1708／Q1709 要求固定打出時影響集合並保留離場來源限制。這些案例需要統一的特徵求值器，不能靠每張卡修改印刷欄位。

CR 10.9.1.1–.6 規定基礎、能力、非數值、數值、依存及時間序。BP16-049 的指定攻體值與 BP01-011 類加值若同時作用，固定「先 set 再 add」會產生與時間序不同的數字；此組合是條文推導的測試情境，不冒稱已有特定 Q&A。

## 決定

採純特徵求值：基礎資訊（進化費用例外）→能力授予／失去／有效性→非數值→數值。Add、Set 同層；不是依操作名固定排序。依 CR 10.9.1.5 比較先套 A 是否改變 B 的適用對象或方式以建依存，不能只看 read/write 交集。每套一個效果重算剩餘依存。

依存無法決定循環先後時，按 CR 10.9.1.6 的發生順序各套一次，再重新處理剩餘效果（generalized）；不尋找數值固定點，不靠迭代次數上限返回基本值。static 的 timestamp 為來源進目前區域時點，其他為適正 play 時點（.6.1–.6.2，official）。相同時間戳採下列專案解讀，不冒稱條文已決。

同批進場而 timestamp 相同沒有直接條文：採「回合玩家控制效果先，同玩家自行排列」，標 `strength: inferred`。CR 1.3.4.1 僅作多人先後精神的類推依據。登錄 D.rule-choice ContinuousTieOrder，選定順序保存並供後續重算沿用，不能每次查值再問；有效集合變動僅續補尚未定序部分，保存舊相對序。

本文 apply 安裝固定集合的效果；static selector 動態。grant 建立獨立能力來源，失去能力不能刪掉無期限的普通 + 修正。入場依 ProspectiveEntry 求值，進場取代及 entry_effects 在掃描入場誘發前生效（10.9.3），initial posture 不另造 act 事件。move、search、create、transform 共用此入口。

事件先檢查允許的數值處理來源，再比該處理實際 delta：從者來源為 Instruction 或 RuleStep(12.2.4.1)；領袖另容許 Damage、Recovery、Payment（Q732 含生命費用，Q2282 三次變動是三次）。Set 增減按 CR 5.27.2，零差不記事件。E.life-change 依 IR 事件登錄為領袖生命 E.stat-change 的 facet 別名，共用 OriginFactId，不建立第二個事實或雙算。

| 判斷                                                           | 強度與依據                                                                                                 |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 進化基礎替換不算、超進化 +1 算                                 | official：Q2758／Q2759／Q2075、CR 5.16.1.2／12.2.4.1                                                       |
| 對手回合的增加也誘發                                           | official：Q2757／Q2760／Q2768／Q2756／Q2761                                                                |
| 持續條件翻轉、期限消失、操縦／箱詰め還原及查詢重算不生數值事件 | `strength: inferred`：以明示數值處理與基礎／派生資訊分離。Q2758 只直接證明進化，不擴充為其他情境的官方裁定 |
| 一個指示對一主體是一事實，攻／體為 facets，or 條件只匹配一次   | `strength: inferred`：保留指示粒度並避免同事實重計；Q2075 只證明會誘發，未證明次數                         |

取代在提案階段處理、每效果每提案一次，自我取代先行，其他按 CR 10.10 的受影響者程序選序，保留 lineage 與 receipt；不是先做原動作再補救。費用固定值先於增減按成本專屬條文，不得套成所有數值的 set/add 順序。額外誘發採附加數相加，Q2602 的兩個 +1 共三次，不能遞迴倍增。

## 考慮過的選項

| 選項                          | 為何不採／採用代價                                                                              |
| ----------------------------- | ----------------------------------------------------------------------------------------------- |
| 所有數字變大都發事件          | 進化會觸發 BP21-P53，直接違反 Q2758；查詢次數還可能影響遊戲。                                   |
| 從者完全不發數值事件          | 超進化和本文加值無法觸發，違反 Q2759；應分辨事件來源而非整族排除。                              |
| 固定 set→add 或 EffectId 順序 | 忽略依存與 timestamp，兩個效果發生順序不同卻被強制得相同結果。EffectId 只是識別，沒有規則意義。 |
| 循環重算直到穩定              | 規則要求逐一套用，不要求數值固定點；可能不收斂，也讓 query 隱含執行無限工作。                   |
| 所有修正都是授予 static 能力  | CP04-PR22 失去能力後修正會消失，違反 Q2540；能力與普通持續效果需分型。                          |

## 後果

求值與事件提交分離，cache 不得有規則副作用。S-008 的六句型設計已補，仍須測進化／超進化、同時攻體、兩個先後指示、同主體的 facet 去重與可使用條件歷史。另測 set/add 的兩種時間序、循環一次、來源失效與入場橫置無假事件。
