# ADR-0007：有型別歷史事實與 UB 可見性

狀態：已採用（2026-09-28）。規則版本：CR 1.27.0。

## 背景

CP04-P86 的 Ames UB 可以在本文發動 CP04-003 的 Eris UB。Q2391 明確回答，原有兩次發動時，Eris 查詢必須已把仍在結算中的 Ames 算成第三次。Q2390 同時要求「不含這次」只排目前執行，過去同一張 Eris 的發動仍計。若只數完成日誌或排除同卡名，至少一項必然錯誤。

CP04-P72／P80 的 Q2467／Q2471 說拒付或無合法目標不算發動，CP04-P54 的 Q2531 則說本文條件不成立仍算。CR 14.5.1.3 定義適正打出且解決；10.6.2.7 的打出事件與 .8 解決相鄰，沒有允許對手插入的檢查時點。資料結構需要表示「適正」，但不需要為無可觀察差異再建一組完成生命週期。

## 決定

H.fact 保存 OriginFactId、主體當時特徵／controller／cause、execution、batch、visibility。H.query 封閉事件型別、欄位、聚合與時間窗：CountFacts、CountSubjects、Sum、Exists 分開；CurrentTurn 用 TurnId，不能用目前 UI 日誌範圍猜。

UBActivation 為 E.play 的 facet，僅在適正打出完成（10.6.2.7）建立，qualification=ProperPlay；沒有 InFlight／Completed。此資料模型由相鄰程序與 Q2391 結果類推（generalized），不是說官方條文省略了「解決」。打出嘗試、選待機、未付費不產生事實；本文全不適用仍有事實。

ExcludeCurrentExecution 只排查詢者 execution；外層、過去同卡與其他來源保留。任何對 UB 和 ability_played 的合取／any_of 共享 OriginFactId 去重；結算結束不另發第二個 UB 事件。誘發待機仍按 CR 10.7 在下一個檢查時點打出，不在巢狀本文中插隊。

模式使用另以 AbilityInstance、TurnId、ModeId 記錄，適正 play 提交。擲骰以 RollId 保存程序最終接受值，Q2206 排除重擲前值；多個 attempts 不是多次發動。領袖生命事實的次數、變動量分開，Q732 生命費用仍可計次。

## 考慮過的選項

| 選項                        | 為何不採／採用代價                                                                                                       |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 只數完成的 resolve 日誌     | Ames 未完成，Eris 看不到第三次，直接違反 Q2391。不能用特殊加一補洞，因為巢狀可有多層。                                   |
| 只要按下發動就計            | Q2467／Q2471 的拒付與非法目標也被計入；必須以完成打出程序的事實為界。                                                    |
| 進結算 eligible、完成再發布 | 能做出相同結果，但要合併執行 stack 與已完成歷史，還有重複提交風險。CR 的相鄰步驟沒有需要這個狀態的可觀察差異，因此刪除。 |
| 以卡名排除本次              | 過去三次 Eris 也被排掉，違反 Q2390；execution 是正確粒度。                                                               |

## 後果

歷史查詢不再依賴內部執行 stack 的聯合視圖，減少完成後重計的狀態。回歸期望固定：原有 2 次→Ames 記錄後 3 次→Eris 查詢排自己得到 3→兩者完成後總計 4。另測拒付為 0、本文 false 仍 +1、同卡過去發動不被排除。

## 未決事項

網路事件與內部事實的投影格式待實作；新增 facet 不能自動成為新的公開封包。若未來規則容許適正 play 後取消解決，須重新評估單事件等價性，不靜默修改此語義。
