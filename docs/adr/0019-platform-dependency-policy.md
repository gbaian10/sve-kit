# ADR-0019：支援平台與依賴選型

狀態：已採用（2026-10-04）。支援範圍指開發、測試與建置主機。

## 背景

專案開源後，其他人必須能在自己的機器開發。
[#312](https://github.com/gbaian10/sve-kit/issues/312) 稽核發現系統函式庫版本綁定、主機路徑假設，
以及已有標準或成熟套件卻自行實作的通用功能，增加安裝、相容與維護成本。

## 決定

支援平台定為 Linux 與 macOS；macOS 相容工作延後，依 [#315](https://github.com/gbaian10/sve-kit/issues/315) 處理，
不宣稱目前已完成驗收。Windows 不支援，[#316](https://github.com/gbaian10/sve-kit/issues/316) 僅記錄已知問題。
此範圍不等於 Web 使用者的瀏覽器平台限制。

通用 parser、Schema 驗證、簽章、鎖、queue、CLI 與標準格式，優先用標準庫或維護中的成熟套件；
不得自行撰寫通用解析器。「避免加依賴」不能單獨作為自寫的理由。
專案仍負責來源限制、遊戲規則、跨列引用等業務檢查，以薄層接到套件，不重做其解析機制。

選型記錄授權、支援平台、必要行為、效能／大小及維護狀態；沒有套件能滿足時，寫明具體技術缺口，
不把缺口當成自行寫解析器的默許。新依賴先以只加依賴的小 PR 審查，再接實作。
資料與下載位置由環境變數或參數傳入，不綁定維護者的機器、私人路徑或特定 OS 套件版本，
例如固定系統 libbrotli 版本；專案依賴仍以套件管理器及 lockfile 管理。

## 考慮過的選項

| 選項 | 取捨 |
| --- | --- |
| 只支援維護者的 Linux 環境 | 本機改動最少，但他人難以重現開發環境，不採用 |
| 同時承諾 Linux、macOS、Windows | 可涵蓋更多開發者，但 Windows 的平台差異超出目前投入範圍，不採用 |
| Linux 與 macOS、通用功能採標準庫／成熟套件 | 採用；macOS 分階段完成，以明確平台範圍控制維護成本 |
| 優先自寫以減少依賴 | 減少套件數卻增加標準行為、相容性與測試的維護責任，不採用 |

## 後果

既有通用實作依 [#317](https://github.com/gbaian10/sve-kit/issues/317)、
[#318](https://github.com/gbaian10/sve-kit/issues/318)、[#319](https://github.com/gbaian10/sve-kit/issues/319) 逐步替換。
審查須檢查可攜性與選型依據，並驗證替換後仍滿足必要行為；格式或重播序列改變時明示版本邊界。
採用套件不取代專案的業務驗證，也不代表可忽略授權、維護狀態或效能成本。
