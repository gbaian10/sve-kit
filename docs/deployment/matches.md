# 對局狀態、恢復與工作區清理

本頁只記錄未來 Durable Object 對局的已確認約束，沒有核可整份後端平台提案。
`sim/server` 尚未建立；現有本機引擎的存檔能力不代表線上重連、休眠喚醒或歸檔已完成。
部署分工見 [部署邊界](architecture.md)。

## 對局狀態的權威與可見性

依 [ADR-0001](../adr/0001-engine-skeleton.md)，每局只有一份權威狀態。
玩家與 AI 只取得 `Observation` 與獲授權的 `DecisionView`；
續體、完整狀態與私有候選保留在權威端。內部事件與歷史事實不能直接當作網路封包。

這個約束也適用於恢復後重新送出的資料。依
[AGENTS 的資訊洩漏原則](../../AGENTS.md#已定案的設計原則)，
未公開的對手手牌不能攜帶可追蹤的固定 ID。重連不擴大玩家可見範圍。

## 恢復所需的引擎資料

[ADR-0001](../adr/0001-engine-skeleton.md) 要求重播保存權威決定與隨機輸入的版本，
觀察者重播仍套相同可見性；不能只靠玩家已收到的公開投影還原權威狀態。
[ADR-0012](../adr/0012-version-meta.md) 要求卡表快照版本、CR／裁定版本與引擎版本獨立記錄。
這些既有約束適用於對局恢復，不在此另訂資料表或封存格式。

現有 [`Replay`](../../sim/engine/src/replay.rs) 原型有 `save`／`restore`，
保存含完整 `Game` 的節點圖，存檔格式標為 `astra-save/1`；`restore` 的輸入是受信任存檔。
它不是 Durable Object 儲存轉接層，也不是供玩家上傳的不可信存檔驗證器。
[引擎現況](../sim/engine-status.md#回放輔助與資訊邊界) 的相關封存記錄仍有待重新確認，
不能以本機 API 的存在宣稱已有線上恢復保證。

## Durable Object 工作區與清理

維護者在 2026-09-25 的部署討論中明示確認：Durable Object 的對局儲存須由應用程式
依規則清理，不能假設對局結束後平台會自動丟棄資料。整理來源由
[#473](https://github.com/gbaian10/sve-kit/issues/473) 指定。

對局工作區與供觀看、診斷使用的回放歸檔是不同用途。這項清理要求沒有指定回放的保存期限，
也沒有核可 D1／R2 的歸檔目的地、對局登記表狀態機或 Alarm 排程。
本輪沒有已確認的跨儲存歸檔／刪除流程可轉為正式契約；其確認由 #473 追蹤。
回放的已採用資訊與公開資產邊界見 [回放契約](replays.md)。
